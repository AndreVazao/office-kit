# Office Kit — Avatar Studio (isolated prototype)

This directory is a standalone character-authoring prototype. It does **not** import, modify, register with, or depend on `packages/scene-engine`, `packages/core`, or `packages/windows-host`. It is intentionally excluded from the root test/build scripts until the module has its own acceptance criteria.

## Run

Serve this directory with any static HTTP server (ES modules and WebGL require HTTP):

```bash
cd avatar-studio
python -m http.server 8000
```

Open `http://localhost:8000`.

Three.js and its GLTF exporter are loaded from the pinned jsDelivr CDN import map. A network connection is required on first load.

## Current prototype

- Procedural, editable human and robot base meshes.
- Human presets for André (CEO), three masculine body types, three feminine body types, and a humanoid robot. The André preset now uses a receding/bald crown with short grey temple hair, a wider face/nose starting profile, and a long tapered grey beard silhouette based on the supplied frontal identity reference; these are explicit hand-authored proportions, not an automatic 3D reconstruction.
- Height, body build, head size, shoulder width, face width, jaw width, nose volume, eye spacing, and hair length controls.
- Hair colour and four procedural hairstyles (short, classic, long, tied), beard variants, suit, casual, and tactical clothing variants.
- Rounded visual joint caps at limb endpoints, suit detailing, orbit camera, six preset camera angles (front, 3/4, both profiles, back, top), neutral studio lighting, and GLB export.
- A THREE.Bone / THREE.Skeleton rig with linear-blend skinning on the upper arms, forearms, separate thigh/shin segments, pelvis, and torso shells. The visible limb cylinders are replaced by SkinnedMesh objects weighted between their corresponding joint bones. Thigh and shin are separate meshes with a dedicated knee bone and ankle/foot bone; upper-thigh weights transition from the pelvis into the thigh and knee.
- Outfit attachment: shirt, lapels, tie, buttons, and pocket square follow the chest bone; shoulder shells blend between the chest and upper-arm bones. Robot manipulators and shoulder, elbow, and wrist details follow their corresponding arm/hand bones.
- Procedural idle, walk, sit, talk, and work poses deform the skinned limb segments and body shells. The walk cycle alternates left/right stride and knee recovery, adds ankle/foot roll, counter-rotation through the torso, and subtle wrist swing; sitting, talking, working, and idle poses also include controlled hand, wrist, and torso motion. Human hands now use three-bone chains for each finger and thumb; each phalanx is independently weighted and pose modes drive progressive joint flexion. The optional skeleton helper is a visual inspection overlay.
- GLB export samples the five procedural modes into skeletal animation clips (30 FPS by default), including bone rotation and facial eyelid scale tracks. The editor restores the selected preview mode after sampling. These are reusable basic clips, not motion-capture or production animation.
- All character parameters are local to this app; no backend calls or credential access.

## Multi-device graphics quality contract

Avatar Studio defines four delivery profiles in `src/quality-profiles.js`: Ultra, High, Medium, and Low. Each profile declares target hardware, triangle/material/texture budgets, facial/hair/hand detail, shadow level, animation support, and a suggested preview pixel ratio. The selected profile is deliberately **not** chosen by Avatar Studio: the Office Kit runtime must inspect the actual device/session and select the best supported profile, with a safe fallback.

The GLB root carries this contract in standard glTF `extras` metadata (`officeKitAvatar`), including schema version, profile definitions, and the `runtime-owned` selection policy. This lets a future reviewed adapter read the available tiers without coupling the standalone editor to runtime packages.

**Current implementation:** the GLB export selector generates one profile-specific file at a time. Ultra retains source geometry; High, Medium, and Low run a deterministic vertex-clustering pass per mesh. The pass clusters spatially and quantizes UV coordinates at the same relative LOD scale so vertices can merge within a UV island without collapsing the 0/1 seam; material-group, secondary-UV, hard-normal, tangent-handedness, and vertex-colour buckets remain separate. It averages ordinary and morph-target attributes into newly sized output buffers (never reuses source-sized morph arrays), decodes normalized integer attributes into float output, renormalizes normals/tangents, and aggregates the four strongest bone influences before normalizing skin weights. A proportional largest-remainder allocator distributes the global triangle budget across visible meshes, and the export report records each mesh's source, target, and achieved triangle count. The validator checks attribute/morph vertex counts, indices, contiguous and complete material-group coverage (including a source-geometry preflight before clustering), finite attribute values, four-component skinning data, valid bone references, and normalized weights. A mesh with gaps, overlaps, or invalid material-group ranges is rejected before reduction so triangles cannot silently disappear. Export is blocked if the selected profile's triangle budget is not reached; it no longer produces a knowingly out-of-budget GLB. The exporter records source/optimized triangle counts, vertex count, selected profile, and validation report in `officeKitAvatar.exportedVariant`. The original editor geometry is restored after export.

**Validation boundary:** this is a first geometry-reduction pass, not a certified production LOD pipeline. Untextured single-material meshes now consolidate into profile-specific vertex-colour material classes, with roughness/metalness precision reduced only as needed to meet each material budget. Texture dimensions are audited across standard/physical material slots and nested ShaderMaterial uniforms. Oversized image-backed textures that the browser can safely draw (HTML images, canvases, and compatible image sources) are copied to a new canvas at the profile's maximum dimension, with aspect ratio preserved; cloned textures retain their sampling/transform settings, cloned materials and uniform trees reference only the resized copies, and the source images/materials are restored untouched after export. Unsupported sources (including DataTexture/raw pixel buffers, compressed textures, video/image sources the browser cannot draw, and unverifiable dimensions) remain blocked rather than being mutated or silently exported. This is per-texture resizing, not atlas generation; atlas packing and automated visual-equivalence checks remain pending. Automated visual-equivalence checks, stress tests across every real avatar preset, and external GLB playback acceptance are still pending. The standalone browser harness now includes representative real SkinnedMesh vertex-deformation checks for walk/sit/talk/work (including limb, knee, foot, torso, neck, jaw, hand and finger targets), normalized skin-weight/index validation, and a GLB export/reimport round-trip that verifies all five animation clips. These checks are implemented but remain manual until the browser harness is executed. Clustering can alter silhouette or surface detail, and a mesh can remain above budget if its topology cannot be reduced safely enough. Inspect every exported profile before distribution. The Office Kit engines remain untouched and own device capability detection, runtime selection, and fallback.

## Multi-device graphics quality contract and source audit

Four target profiles (Ultra, High, Medium, Low) are defined in `src/quality-profiles.js`. The editor now measures the actual visible post-rig avatar geometry: triangle count, vertex count, visible mesh count, skinned mesh count, and unique material count. It displays whether the current source model fits each profile's triangle and material budgets. The measured source metrics and profile-fit results are embedded in the exported GLB root extras.

The Studio does not detect the user's device and does not select a runtime profile. The Office Kit runtime remains the sole authority for capability detection, profile selection, and fallback.

**Current limitation:** the editor audit reports source-model fit, while each explicit GLB export applies the selected geometry profile. A profile export is not proof of device performance or visual equivalence. The runtime still makes the device-specific selection; Avatar Studio only authors and exports variants.

## Quality-variant structural check

Serve the directory over HTTP, then open `/quality-variant-check.html`. The isolated browser harness builds a skinned test mesh with float UVs, normalized integer UV2s, vertex colors, tangents, a morph target, and two material groups, runs Ultra/High/Medium/Low through the production reducer, checks triangle budgets and structural invariants, verifies morph-target remapping and proportional distribution of a global budget across two meshes, verifies material consolidation on two differently coloured meshes, proves direct material variants leave source geometry untouched, rejects unsupported oversized DataTexture and ShaderMaterial-uniform sources, verifies a 1024×256 image-backed texture is resized to 512×128 for Low without mutating its source and that the original material is restored, verifies two independent ShaderMaterial texture uniforms (1024×256 and 1024×1024) are both resized to the Low limit while preserving aspect ratio, original image sources, and restoration, verifies meshes sharing one textured material reuse a single resized material/texture and restore the shared source reference, builds a procedural rig and validates all five exported animation clips for finite ordered samples, complete bone tracks, non-static motion, and selected-pose restoration; builds a representative skinned avatar fixture and checks normalized skin weights, valid bone indices, and actual vertex deformation across walk/sit/talk/work for limbs, knees, feet, torso, neck, jaw, hands and fingers; exports that rig to binary GLB, reimports it with GLTFLoader, verifies the skinned meshes and expected bone hierarchy survive, and runs a playback smoke test for all five clips by checking that animation updates the imported skeleton matrices; confirms restoration after every profile, and injects an invalid material reference to verify rollback on validation failure, and creates an intentional material-group gap to verify source preflight rejection. This is a manual browser acceptance tool; it is not part of the root Office Kit CI and does not replace visual inspection of real avatar exports.

The export validator rejects malformed indices, invalid material groups, non-finite positions, missing skin attributes, invalid bone references, and non-normalized skin weights before allowing a profile export to proceed. Its report is embedded in the GLB metadata.

## CEO identity-reference workflow

The right-hand identity panel accepts a local JPEG, PNG, or WebP reference image (maximum 15 MB). The image is decoded and drawn in the browser only; it is not uploaded, committed, persisted, or transmitted by this module. The user can mark fourteen facial reference points on the image to create a manual landmark guide (crown/top of head (not hairline, to support shaved heads), brows, eyes, nose tip, cheek width, mouth, chin, jaw width, and nasal wings). Only the current browser session holds the selected image and points.

The isolated editor also exposes manual facial proportion controls for face width, jaw width, nose volume, eye spacing, and hair length. After all fourteen landmarks are marked, the user can apply initial estimates for face width (measured from crown to mouth rather than beard tip), jaw width, nose size, and eye spacing to the live avatar. The workflow also samples median skin tone from cheek patches and beard tone from the lower-beard patch on a private scratch canvas, then applies those colors to the André preset. Landmark ordering is checked before fitting; the controls remain manually adjustable. The estimate is a modeling aid, not automatic face recognition or 3D reconstruction. The André CEO preset has a dedicated starting profile derived from the supplied frontal photo (bald crown, short side hair, broad face/nose, long tapered grey beard). Its head silhouette now uses a deformed high-resolution sphere with a wider lower-face profile, subtle cheek projection, and tapered temple transition rather than stacked generic head/jaw ellipsoids. The nose is built from deformed high-resolution bridge and tip meshes with separate alar wings, improving the front/three-quarter/profile silhouette. The manual landmark workflow derives jaw and nasal-wing ratios in addition to face width and eye spacing. These are proportion-fitting aids, not a verified likeness or automatic reconstruction. A single frontal photo cannot reveal the true side, rear, skull depth, ear depth, or hidden geometry. A faithful likeness requires additional user-supplied views (front, both profiles, and 3/4), consistent lighting where possible, and iterative manual sculpting. Do not claim a likeness is complete until it has been compared against the user's reference views.

## Deliberate limitations

This is a first procedural blockout, not a photogrammetric reconstruction or production-ready anatomical mesh. Upper arms, forearms, leg segments, pelvis, and torso shells are converted to SkinnedMesh objects with two-bone linear-blend weights. The walk/sit/talk/work poses deform the limbs and central body shells. Head assemblies and palms are converted into rigidly weighted SkinnedMesh parts; each finger and thumb uses a three-bone chain with independently weighted proximal, middle, and distal geometry, allowing progressive digit articulation. Feet are rigidly weighted to their ankle/foot bones. Major suit details and selected robot joint components are now rigidly weighted to the chest, upper-arm, forearm, or hand bones. This is attachment, not full cloth deformation: jacket surfaces, trousers, hip and garment seams, and casual/tactical garment details still need further continuous skin weights and seam refinement; the pelvis now blends across Hips, Spine, and both upper-leg bones at the lateral hip seams; the torso shell blends progressively from Hips through Spine to Chest with normalized three-bone weights. The shirt follows the same waist-to-chest gradient, the neck now uses continuous vertical weights between Chest and Neck, the jaw rotates around a dedicated hinge behind the mouth, and shoulder shells blend into the chest. Facial blendshapes, fine tendon/skin deformation, cloth simulation, full-body skinning, and production animation remain future work. The five exported clips are procedural baseline animations and still require validation in external glTF viewers and engines. GLB export includes the visible skinned limb segments and the assembled static parts; the debug helper is hidden by default. Do not describe the model as a complete production-ready character.

## Isolation contract

Do not add imports from Office Kit runtime packages and do not change root package scripts, dependencies, CI workflows, adapters, transport, persistence, or scene-engine files as part of Avatar Studio work. Future integration must happen through a separately reviewed adapter boundary after this module is independently validated.
